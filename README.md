# Liquid Ass

Публічний набір адаптованих компонентів і налаштувань **Hyprland + DankMaterialShell Glass**: верхня glass-панель на кожному моніторі, кнопки робочих столів зі штатного DMS WorkspaceSwitcher, селектор *робочих столів* з композицією вікон, меню застосунків і вибір шпалер. Шпалери можуть керувати динамічною палітрою DMS; статична sage-палітра додається як альтернативний пресет.

## Вміст

- `plugins/glassShell/` — основний локальний DMS composite-плагін (QML, маніфест). Меню перемикає застосунки, селектор перемикає **робочі столи**, а не окремі вікна.
- `plugins/codexGlass/` — необов'язковий індикатор квоти Codex для панелі. Потребує `~/.local/bin/omp` з командою `usage --provider openai-codex --redact --json`.
- `themes/glass.json` — статичний dark/light sage-пресет; **не** є поточною динамічною палітрою.
- `examples/plugin_settings.example.json` — очищені від особистих шляхів геометрія селекторів і розкладка панелі. Це фрагмент для перенесення налаштувань, **не** файл для заміни всього `plugin_settings.json`.
- `examples/hyprland-glass.lua` — додаток до існуючого Lua-конфіга Hyprland, не повна конфігурація системи.

## Вимоги та встановлення

Потрібні Hyprland з Lua-конфігом `hl`, Quickshell/DMS **1.6.2+**, активний DMS у сеансі, `dgop` для метрик і `nvidia-smi` лише для NVIDIA GPU-метрики. Для перемикання просторів потрібні реальні робочі столи Hyprland; DMS заповнювачі не клікабельні. Складові використовують DMS `qs.Common`, `qs.Services`, `qs.Widgets` та штатні віджети DankBar. Перевіряйте доступність цих модулів саме у своїй версії DMS.

1. Збережіть свої конфіги. Скопіюйте **вміст** `plugins/glassShell` до `~/.config/DankMaterialShell/plugins/glassShell/`; за бажанням так само `codexGlass`. Увімкніть плагіни у налаштуваннях DMS. Не копіюйте сторонні плагіни чи готові `settings.json` з чужої машини.
2. Вимкніть штатні DMS bar configs, якщо хочете бачити тільки Glass-панель: автоматичне відключення в коді стосується лише двох імен панелей вихідної конфігурації. Збережіть резервну копію свого `plugin_settings.json` і перенесіть параметри з прикладу **лише в секції відповідних плагінів**, не затираючи власні дані; за відсутності прикладу плагін використовує свої значення за замовчуванням. Для нового встановлення приклад містить `migrationVersion`/`layoutVersion`, щоб не запускати міграції старих персональних конфігів.
3. Використайте `examples/hyprland-glass.lua` як зразок доповнення наявного `hyprland.lua`. Залиште **Super+R** для меню. Налаштуйте постійні робочі столи на своїх виходах і запуск DMS у сеансі `Hyprland:DMS`. Панель показується на всіх екранах; автоховання та позиції можна змінити в налаштуваннях Glass.
4. Для кольорів, які оновлюються зі шпалер, виберіть у DMS динамічну тему та ввімкніть його генерацію кольорів. Після генерації `dms.colors` Lua-файл стане доступним Hyprland; не викликайте `require("dms.colors")` до цього. Для незмінного оформлення імпортуйте `themes/glass.json` через DMS замість динамічної теми.
5. NVIDIA-метрика використовує змінну середовища `GLASS_GPU_ID`: у середовищі сеансу DMS встановіть, наприклад, `export GLASS_GPU_ID=0` (індекс, UUID або PCI bus ID `nvidia-smi`). Без неї GPU-поле показуватиме `—`; для інших GPU просто приберіть його з розкладки панелі. Без `codexGlass` або `omp` приберіть `codex` з правого блоку.

Зміни файлів QML можуть потребувати перезапуску **лише** user-служби DMS, а не зміни greeter чи PAM. Не перезапускайте DMS посеред незбереженої роботи. Команди IPC: `dms ipc call glassShell launcherToggle`, `wallpaperToggle`, `workspaceNext`, `workspacePrev`, `workspaceConfirm`; в `examples/hyprland-glass.lua` наведені відповідні клавіші.

## Межі публічного експорту

Особисті шпалери, Steam-бібліотеки, знімки екрана, згенеровані GTK/Kitty теми, локальні налаштування моніторів і `~/.config/DankMaterialShell/{settings,plugin_settings}.json` не включені. Тут немає інсталятора greeter, змін PAM, системних файлів greetd чи копії upstream DMS. Повний вхід через greetd і чисте встановлення на чужій машині цим експортом **не перевірені**. Адаптовані плагіни залежать від API DMS; встановлюйте upstream DMS окремо та зберігайте власні конфіги.
